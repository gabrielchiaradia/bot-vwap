02 Iniciar, parar y reiniciar los bots

Todos los comandos se ejecutan desde ~/bot-vwap como botuser. Los tres containers son vwap-btc, vwap-eth y vwap-dashboard.

Iniciar todo

docker compose up -d vwap-btc vwap-eth vwap-dashboard

Iniciar un bot específico

docker compose up -d vwap-btc    # solo BTC
docker compose up -d vwap-eth    # solo ETH

Parar todo

docker compose down

Parar un bot específico

docker compose stop vwap-btc
docker compose stop vwap-eth

Reiniciar sin reconstruir

docker compose restart vwap-btc
docker compose restart vwap-eth

Reconstruir y reiniciar (después de cambios de código)

docker compose down
docker compose build --no-cache
docker compose up -d vwap-btc vwap-eth vwap-dashboard

Ver estado de todos los containers

docker compose ps
Inicio automático Ambos bots tienen restart: unless-stopped. Si el VPS reinicia, los containers vuelven a levantarse solos.
Riesgo de posiciones abiertas Antes de parar un bot, verificá que no tenga una posición abierta en Binance. Si la tiene, cerrala manualmente primero o el SL/TP quedará huérfano.

07 Health check automático

El script tools/health_vwap.sh verifica cada 5 minutos que ambos containers estén corriendo y generando logs. Si detecta un problema, reinicia el container afectado y manda un mensaje a Telegram.

Instalar el cron (como root)

# Primero desde root (no botuser)
cd /home/botuser/bot-vwap
sudo bash tools/health_vwap.sh --install

Verificar que está instalado

crontab -l    # debe mostrar la línea de health_vwap.sh

Ejecutar manualmente

bash tools/health_vwap.sh

Ver log del health check

tail -30 ~/bot-vwap/dashboard/data/health_vwap.log

Desinstalar

sudo bash tools/health_vwap.sh --uninstall
Qué detecta Dos condiciones: (1) container caído → lo reinicia automáticamente; (2) container corriendo pero sin actividad por 5 minutos → avisa por Telegram pero no reinicia (puede ser mercado sin señales).
08 Correr backtests

Los backtests se ejecutan con Python directamente, sin Docker. Usá el script backtest_vwap_realista.py que incluye comisiones y simulación intra-vela realista.

Backtest simple

python3 scripts/backtest_vwap_realista.py --symbol BTCUSDT --dias 90

Con parámetros específicos

python3 scripts/backtest_vwap_realista.py \
  --symbol BTCUSDT --dias 360 \
  --band-mult 2.0 --rr 0.4 --risk 3

Sweep de múltiples parámetros (separá con comas)

python3 scripts/backtest_vwap_realista.py \
  --symbol BTCUSDT --dias 360 \
  --band-mult 2.0,2.5,3.0 \
  --rr 0.4,0.5,0.6,0.7 \
  --risk 1,2,3

Escanear BTC y ETH en una sola corrida

python3 scripts/backtest_vwap_realista.py \
  --scan --dias 360 \
  --band-mult 2.0,2.5 --rr 0.4,0.5 --risk 1,2,3

Los resultados se guardan en backtest/results/ y se visualizan en el dashboard en http://167.179.114.168:8081.

Parámetros disponibles

ParámetroDefaultDescripción
--symbolBTCUSDTPar a testear
--dias90Ventana histórica en días
--band-mult2.5Multiplicador de banda (acepta comas)
--rr0.5Risk/Reward ratio (acepta comas)
--risk1% de riesgo por trade (acepta comas)
--min-profit0.20% mínimo de reward para tomar la señal
--sweep-rr—Prueba RR = 0.2, 0.3, 0.4, 0.5, 0.7
--scan—Corre BTC y ETH en paralelo
Caché de datos Los datos históricos se cachean localmente en backtest/data/ por 10 días. La primera corrida descarga de Binance; las siguientes son instantáneas.
09 Pasar de Testnet a Real
Precaución Solo pasar a real después de verificar que ambos bots operan correctamente en testnet. El trading con futuros y apalancamiento conlleva riesgo de pérdida total del capital.

Checklist antes de ir a real

VerificaciónOK
Al menos 2 semanas de testnet sin errores críticos en logs☐
SL/TP se colocan correctamente después de cada fill☐
Journal registra todos los trades con PnL correcto☐
Dashboard muestra datos en tiempo real☐
Notificaciones Telegram funcionando☐
Health check instalado y activo☐

Pasos para el cambio

1. Crear API keys reales en Binance → Gestión de API con permisos de Futures.

2. Editar ambos .env en el VPS:

nano ~/bot-vwap/.env.btc
IS_TESTNET=false
BINANCE_API_KEY=tu_key_real
BINANCE_API_SECRET=tu_secret_real
RISK_PER_TRADE=1.0    # bajar de 3% a 1%

3. Hacer lo mismo para .env.eth.

4. Reiniciar ambos bots:

docker compose restart vwap-btc vwap-eth
Recomendación Arrancá con RISK_PER_TRADE=1.0 en ambos bots (1% cada uno = 2% total de la cuenta). Verificá las primeras 5 operaciones reales antes de considerar subir el riesgo.
